# M3: 見どころの抽出

要件定義は [`requirements.md`](requirements.md) が正。本書はそのM3（→ §2.1）の設計と記録。
入力はM2が書き出す属性表（[`m2-plan.md`](m2-plan.md) §2 の「5. 属性」）。

## 0. M3で答えを出すこと

| 問い | 判断のしかた |
|---|---|
| **「ただ飛ぶだけ」から抜け出せるか** | **人が置いていない目的地に向かって飛びたくなるか** |

要件§2.1の方針——**見どころは人手で置かず、属性と地形から計算で選び出す**——が守れるかどうか。
守れなければ都市追加のたびに手作業が発生し、企画が実行不能になる（要件§7）。

**「それらしい場所が出た」では足りない。** 空から見て**何かがあると分かる**こと、
同じ入力から**同じ結果が出る**こと（M2と同じ再現性）まで含めて抽出と呼ぶ。

---

## 1. 使える材料（実測・新宿3km四方 26,559棟）

`M2AttributeExport`が書き出した属性表を数えた。**推測ではなく実データ**。

| 属性 | 状態 |
|---|---|
| `bldg:usage` | 全棟。住宅 8,527 / 共同住宅 6,884 / 不明 2,661 / 店舗等併用住宅 2,547 / 業務施設 2,365 / 商業施設 1,444 / 文教厚生施設 1,264 / その他 200 / 宿泊施設 182 / 運輸倉庫施設 163 / 官公庁施設 152 / 作業所併用住宅 139 |
| `bldg:measuredHeight` | 中央値 **9.7m** / 平均 12.9m / 最大 240.6m。**40m以上は663棟（2.5%）、60m以上は115棟** |
| `bldg:storeysAboveGround` | 中央値 3階 / 最大 55階 |
| `bldg:class` | 普通建物 15,076 / 堅ろう建物 9,558 / 普通無壁舎 1,372 / 不明 551 |
| `uro:...:detailedUsage` | 全棟（より細かい用途） |
| `bldg:name` | **全棟が空。** 建物名は入っていない |
| `bldg:yearOfConstruction` | **存在しない** |

### 1.1 欠測値の罠

**「全棟に入っている」は「全棟で使える」ではない。**

| 属性 | 欠測の表し方 | 件数 |
|---|---|---|
| `bldg:measuredHeight` | **`-9999`** | 708棟（2.7%） |
| `bldg:storeysAboveGround` | **`9999`** | 2,770棟（10.4%） |

空欄ではなく**極端な数値**で入っているので、そのまま計算に混ぜると
「高さ-9999mの建物」「55階建ての小屋」が上位に来る。
**すべてのルールは、まず有効値だけに絞ってから走らせる。**

### 1.2 建物名が空なのは好都合

`bldg:name`は26,559棟すべてで空だった。
**実在建築物の名称を出さない**（`CLAUDE.md` 不変条件4）方針にとって、
そもそも名前が手元に無いのは安全側。**見どころは名前で説明せず、形と位置で示す。**

## 2. 抽出ルール

**空から見て何かが分かるもの**だけを採る。写実的なテクスチャが無い以上、
読み取れるのは**輪郭・高さ・密度の差・地面の模様**の4つしかない（要件§5）。

| ルール | 空から見て何に見えるか | 必要な材料 |
|---|---|---|
| **R1 突出した高さ** | 周りより明らかに高い1棟。遠くから見える | 高さ・位置 |
| **R2 用途の孤立** | 住宅の海の中の1棟（社寺・学校・官公庁） | 用途・位置・底面積 |
| **R3 大きな屋根** | 低いのに広い建物（学校・駅・体育館） | 底面積・高さ |
| **R4 空白** | 建物が無い塊（公園・操車場・境内） | 建物の位置と底面積 |
| **R5 地形の高み** | 見晴らしの丘 | 地形（DEM） |

### 2.1 R1 突出した高さ

高さ上位N棟ではなく、**周囲との差**で採る。上位N棟だと新宿駅周辺に全部集まり、
「街を見て回る」にならない。

- 有効な高さ（`> 0`）を持つ建物のうち、**25m以上**を候補にする
- 半径300m内の建物の高さの中央値と比べ、**2.5倍以上**または**+15m以上**なら採る

中央値9.7mの街で25mは既に目立つ。**都心では40m級でも埋もれ、住宅地では25mで際立つ**——
この差を出すのが目的。

### 2.2 R2 用途の孤立

- 半径200m内で、**同じ用途が10%以下**の建物
- かつ、その建物の底面積が半径内で**上位20%**

面積の条件を入れるのは、**小さな異物は空から見えない**ため。
実データでは文教厚生施設1,264棟・官公庁施設152棟・宿泊施設182棟あたりが該当し、
住宅と共同住宅（合わせて15,411棟＝58%）の海に対する異物として機能する。

### 2.3 R3 大きな屋根

- 底面積が街全体の**上位0.5%**
- かつ**高さ30m以下**

高さを制限するのは、**塔ではなく屋根**を拾うため。R1と役割を分ける。
学校・駅舎・ホール・倉庫が該当し、これらは上から見た時の面積がそのまま情報量になる。

### 2.4 R4 空白（密度の谷）

**建物の属性を一切使わない。** どの都市でも同じように効く。

- 50mの格子で建物の被覆率を出す
- 被覆率がほぼ0の格子が**2ha以上**まとまっていて、周囲が市街地なら採る

新宿御苑・明治神宮外苑・操車場のような「街の中の穴」が出る。
**空から見た時に最も分かりやすいのは、実は建物ではなく空白**。

### 2.5 R5 地形の高み

- 地形（DEM）を50m格子で標本化し、半径500m内で**+20m以上突出した点**

新宿は平坦なのでほとんど出ない。**出ない都市があって構わない**ルールで、
神戸・長崎・尾道のような地形の街を足した時に効く。

### 2.6 採らなかったルール：階高

「階数の割に高い建物＝倉庫・体育館・ホール」を狙って計算したが、**採らない**。

階数2以上・高さ8m以上に絞った17,566棟のうち階高5m以上は1,625棟で、
その内訳は**住宅578・共同住宅284**と、本来該当しないはずの用途が半分を占めた。
**階数のデータが小さい建物では信用できない**ということなので、ルールとして成立しない。

**測ってから落とした**という記録として残す。

## 3. 選び方（密集させない）

ルールごとの候補をそのまま全部出すと、繁華街に固まる。

- 候補にルール内で0〜1のスコアを付ける
- **スポット同士は250m以上離す**（近い方を捨てる）
- **1ルールが全体の40%を超えないようにする**（種類の偏りを防ぐ）
- **採るのはルールごとに順番に1つずつ**（→ 6.3）
- 総数は**1km²あたり2.8個**を目安にする（3km四方で約25個）

> 当初「1km²あたり8個（3km四方で約25個）」と書いていたが、3km四方は9km²なので
> 8個/km²だと72個になり、両立しない。**具体的な個数のほう**——3km四方で約25個、
> つまり平均600mおきに1つ——を採った。実装では`-ffm3-density`で上書きできる。

**乱数を使わない。** 同じ入力からは同じスポットが出ること（M2と同じ再現性）。
オンライン対応（要件§12）でも、全クライアントで同じスポットが出る必要がある。

## 4. 出力

`Assets/Resources/spots-<都市名>.json`。位置表（`tile-catalog.json`）と同じ扱いで、
**実行時は読むだけ**にする。

```json
{ "spots": [ { "id": "…", "kind": "height|usage|roof|void|terrain",
               "position": {"x":0,"y":0,"z":0}, "radius": 60, "score": 0.82 } ] }
```

**名前は持たせない**（→ §1.2、不変条件4）。表示するのは種類と距離だけ。

### 4.1 誘導は光の柱1本

要件§2.1のとおり、未発見のスポットにだけ**遠景に細い光の柱**を立てる。
近づくと消えて建物そのものが見える。**LOD1の箱でも成立する**表現で、
遠景タイル（`m2-plan.md` §4.6）が無地の箱であることと相性が良い。

## 5. コース（チェックポイント）

**試遊で自然に出た遊び方。** 飛んでいると「決められた線を通りたくなる」。
要件§2は「制限時間・スコアを主軸にしない」「失敗の概念を持ち込まない」なので、
**主軸にせず、失敗も作らない形**でだけ載せる。

| 論点 | 決めたこと |
|---|---|
| コースを誰が作るか | **抽出したスポットから自動生成**。手で置くと都市追加が止まる（不変条件7） |
| 形 | スポットを5〜8個つないだ環状路。`FlightBenchmarkPath`のCatmull-Romをそのまま使える |
| リングの間隔 | 経路上に約200mおき |
| リングの高さ | 経路の周囲の建物の高さから決める。**ビルの谷間を通す配置も、屋上すれすれも計算で作れる** |
| 障害物 | **当たり判定を足さない。** 飛行中は建物をすり抜けたまま（不変条件3）。リングを通ったかだけを数える |
| 失敗 | **無い。** 抜けそこねたら戻って抜ければいい |
| 時間 | **コースを始めた時だけ**時計を出す。自己ベストのみ記録。ランキングは作らない |

**「障害物を避ける緊張感」はリングの置き方で作る。** 当たり判定ではなく、
通れる隙間を狙わせることで出す。

## 6. 実装

| ファイル | 役割 |
|---|---|
| `M3BuildingIndex.cs` | タイルを開いて**位置・底面積・地形**を測り、`Data/Plateau/attributes/geometry.csv`・`terrain.csv`に書く |
| `M3SpotExtract.cs` | 属性表と幾何索引から5ルールを走らせ、`Assets/Resources/spots-<都市>.json`を書く |
| `SpotCatalog.cs` | 実行時に読むだけの一覧（`TileCatalog`と同じ扱い） |
| `SpotBeacons.cs` | 未発見のスポットに光の柱を立てる（§4.1） |
| `M3SpotSetup.cs` | 柱のマテリアルを資産として作り、試遊シーンに載せる |

```powershell
# タイルを測り直して抽出（9枚）
& $U -projectPath $P -batchmode -quit -logFile spots.log `
  -executeMethod FeelFreeFlying.EditorTools.M3SpotExtract.Build -ffm2tiles-grid $G

# しきい値だけ変えて抽出し直す（タイルを開かないので数秒）
& $U -projectPath $P -batchmode -quit -logFile spots.log `
  -executeMethod FeelFreeFlying.EditorTools.M3SpotExtract.Extract
```

### 6.1 底面積は外接箱で測らない

§6で「属性表に足す」としていた底面積は、**タイルのメッシュから測って別表にした**。
属性表はCityGML由来のもの（`M2AttributeExport`）で、そこに幾何を混ぜると
出所の違うものが1つの表に同居する。位置も同時に要るので、表を分けたほうが素直だった。

面積は**上を向いた三角形をXZ平面に落として合計する**。外接箱で測ると、
L字の建物も中庭のある建物も実際より広くなり、「大きな屋根」（R3）が
形だけ大きい建物で埋まる。屋根に張り出しが無い限り、この合計は真上から見た面積に一致する。

### 6.2 高さの欠測は形で埋める

`bldg:measuredHeight`が`-9999`の708棟（§1.1）は、**取り込んだ形の高さ**で代用する。
属性が無いだけで建物は画面に出ているので、その高さは少なくとも嘘ではない。
「有効値だけに絞る」（§1.1）が禁じているのは`-9999`を数値として混ぜることであって、
欠測した建物を街から消すことではない。

### 6.3 スコア順に上から採ると、候補の少ないルールが消える

最初の実装は全候補をスコア順に並べて上から採った。結果、**空白（R4）の候補2個が
どちらも入らず**、40%の上限に達した「高い建物」と「まわりと違う建物」だけで枠が埋まった。
**上限は偏りを止めるが、入ることを保証しない。**

スコアはルールをまたいで比べられる量ではない（それぞれ別の式で0〜1にしただけ）ので、
横並びに比べること自体をやめ、**ルールごとに順番に1つずつ**採る形にした。

### 6.4 道路が入っていないので、街全体が1つの空白になる

R4の最初の実装は候補が2個しか出なかった。取り込んでいるのは建築物と土地起伏だけで
**道路が入っていない**ため、道路も空白として数えられる。道路は街の隅々までつながっており、
公園も操車場も道路経由で1つの巨大な塊になって、「街の端に触れる」という理由で丸ごと落ちていた。

**空白の格子を1つ内側へ削って**（8近傍がすべて空白の格子だけ残す）から塊を数えると、
幅1格子（50m）の道路は消え、広がりのある空白だけが残る。
実測では空白848格子 → 削った後85格子 → 塊18個 → 採用1個。

### 6.5 スコアが上限に張り付くと、順位がidの文字列順になる

「しきい値の4倍で1.0」と切っていたため、中央値9.7mの街では100m級の建物がすべて1.00になり、
**順位がスコアではなく識別子の文字列順で決まった**。結果、高い建物10個が全部西新宿に並んだ。

- スコアは`x / (x + k)`にした。単調で、いくら大きくなっても1に達しない
- それでも一角に固まりうるので、**1km四方あたりの上限**を併せて持つ

250m離すだけでは、超高層の集まる一角に10個が250m間隔で並ぶだけになる。

### 8.1 新宿3km四方での内訳（2026-08-10）

建物 26,559棟（属性の欠けた棟は0。高さを形から代用した棟は708＝`-9999`の件数と一致）。

| ルール | 候補 | 採用 |
|---|---|---|
| R1 突出した高さ | 2,181 | 10 |
| R2 用途の孤立 | 966 | 10 |
| R3 大きな屋根 | 43 | 9 |
| R4 空白 | 1 | 1 |
| R5 地形の高み | 0 | 0 |

- **1km四方13区画に散り、最も多い区画でも4個**（→ 6.5の区画上限が効いている）
- **R5が0なのは想定どおり**（§2.5）。新宿は平坦で、地形の街を足した時に効くルール
- **R4が1個しか出ないのは要観察。** 道路を削る処理（6.4）を入れても、この3km四方には
  2ha以上まとまった空白が1か所しか無かった。新宿御苑・明治神宮外苑は

**「人が置いていない目的地に向かって飛びたくなるか」（§0）は、飛ぶまで分からない。**
30個という数字も、光の柱の見え方も、実際に飛んで確かめる段階に来ただけで、
まだ合否は出ていない。
