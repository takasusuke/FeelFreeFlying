# M1: 飛行の操作

要件定義は [`requirements.md`](requirements.md) が正。本書はそのM1（→ §8）を進めるための手順と記録。
**PC作業。** 移動中には実行できない（→ [`../../CLAUDE.md`](../../CLAUDE.md) §3）。

M0（技術検証）の結果は [`m0-plan.md`](m0-plan.md)。

## 0. M1で答えを出すこと

| 問い | 判断のしかた |
|---|---|
| **続行するか** | **飛んでいて気持ちいいか。** 駄目なら企画中止（`requirements.md` §8） |
| 操作方式 | 入力・速度域・上昇下降の扱いを確定させる（§11の未決事項） |

**これは数値では決まらない。** M0はfpsで判定できたが、M1は試遊して決めるしかない。
だからこそ**判断を先延ばしにしない**。「もう少し作り込んでから判断する」を繰り返すと、
面白くない企画に時間を積むことになる。

判定の目安として、試遊のたびに次の3つに答える。

1. **街を見に行きたくなるか。** 操作に気を取られて景色を見ていないなら、操作が難しすぎる
2. **止まりたくならないか。** 速すぎて目が回る／遅すぎて退屈、はどちらも失敗
3. **もう1周したくなるか。** 1周して満足してしまうなら、それは「移動」であって「飛行」ではない

## 1. 試し方

```
# 都市を取り込む（済んでいれば不要。→ m0-plan.md §3.2）
Unity.exe -projectPath . -batchmode -logFile <ログ> `
  -executeMethod FeelFreeFlying.EditorTools.M0CityImport.ImportFromCommandLine -ffimport-granularity area

# 試遊シーンを作る（都市を入れ直したら作り直す）
Unity.exe -projectPath . -batchmode -quit -logFile <ログ> `
  -executeMethod FeelFreeFlying.EditorTools.M1SceneSetup.CreateFlightScene

# ビルドして実行
Unity.exe -projectPath . -batchmode -quit -logFile <ログ> `
  -executeMethod FeelFreeFlying.EditorTools.M1PlayerBuild.BuildWindows64
Build\M1\FeelFreeFlying-M1.exe
```

メニューからも実行できる（`Tools > FeelFreeFlying > M1: 試遊シーンを作る` / `M1: 試遊用にビルドする`）。

**操作感はEditorのGame Viewで判定しない。** フレームレートも入力の遅れも実行ファイルと違うため、
「気持ちいいか」が環境のせいで揺れる。

**街は仮の箱にしていない。** 要件上は箱でよいが、M0で本物の新宿（2km四方・LOD1）が手元にあるので
それを使う。開始地点は街の中心から900m手前・高度180mで、街に向かって飛び込む形にしてある。

**視点は一人称が既定**（Cで三人称に切り替え）。一人称のときは**自分の姿を消している**。
腕が見えるほうが身体で飛んでいる感じが出ると考えて最初は残したが、実際には視界の中央を
塞いで街が見えなくなった。姿は三人称で見えれば足りる。

> これは`requirements.md` §9（三人称を基本とする）と食い違う。**試遊の結果として一人称を採ったので、
> M1の判断が固まった時点で要件側を書き換える。**

## 2. 操作

飛行中:

| | ゲームパッド | キーボード / マウス |
|---|---|---|
| 傾ける（旋回・機首） | 左スティック | マウス |
| 加速 / 減速 | R2 / L2 | W / S |
| ロール | 左スティック左右 | A / D |
| 機首の上下 | 左スティック上下 | ↑ / ↓ |
| ブースト | A | 左Shift |
| 水平に戻す | B | Space |
| **着地する** | **X** | **F** |
| **視点（一人称 / 三人称）** | **Y** | **C** |
| **上下反転の切り替え** | **十字上** | **I** |
| 開始地点に戻る | SELECT | R |
| **カーソルを返す** | — | **Esc**（クリックで操縦に戻る） |

歩行中（屋上・地面）:

| | ゲームパッド | キーボード / マウス |
|---|---|---|
| 歩く | 左スティック | W A S D |
| 見回す | 右スティック | マウス |
| 走る | A | 左Shift |
| ジャンプ | B | Space |
| **飛び立つ** | **X** | **F** |

> **解放手段の無いカーソルロックを作らない。** ウィンドウ表示のビルドでカーソルを閉じ込めると、
> 他のアプリはおろかウィンドウを閉じることもできなくなる。一度これをやった。

**ヨーの直接入力を持たない。** 傾けて曲がる（バンク旋回）だけにしてある。操作が減るぶん、
街を見ることに集中できる。ラダーが要ると感じたら、それは操作方式の設計ミスなので記録する。

**上下は既定で反転**（マウスを上へ動かすと機首が上がる）。飛行機の操縦桿式（上で機首下げ）が
初期値だったが、試遊で逆にした。**矢印キーだけは反転の対象外**で、常に↑が機首上げ——
明示的に「上げる／下げる」と押すキーが反転するのは分かりにくいため。

マウスは**画面中央からの仮想スティック**として扱う（生のデルタではない）。デルタだと手を止めた
瞬間に機体も止まり、浮いている感じが消えるため。

## 2.1 画面と世界

**表示は3つだけ。** 速度（km/h・大きく）、高度、画面上部の方位帯。
計器を作り込まない——見るべきは街であって数字ではない（`requirements.md` §5）。

方位帯は数字ではなく帯にしてある。旋回中に**どちらへ回っているか**が見えるようにするため。
PLATEAUはEUN（東・上・北）で取り込んでいるので、**Unityの+Zが北**になる。

**取り込んだ範囲の外は海。** 街は2km四方しか無く、その外へ出ると何も無い空間に出てしまい、
箱庭だと分かってしまう。海面（40km四方の板）を街の最下点の2m下に置いて埋めてある。
地形の縁が海に落ちて島のように見える。**水の表現は作り込まない**（M5の課題）。

見た目の確認は画面のスクリーンショットではなく、シーンのカメラから直接書き出す。

```
Unity.exe -projectPath . -batchmode -quit -logFile <ログ> `
  -executeMethod FeelFreeFlying.EditorTools.M1Preview.Capture -ffpreview-out <出力先.png>
```

**人型・マント・カメラ位置はこれで詰めた。** 最初はマントが後方から見て正対する板になり、
身体を完全に隠していた（カメラが機体の上にあり、水平なマントの面を見下ろしていた）。
HUDはIMGUIなのでこの画像には写らない。

## 3. 飛行モデル

**航空力学は再現しない**（`CLAUDE.md` 不変条件3）。失速・迎え角・エンジン出力・揚力は無い。
姿勢角を直接積分し、速度は別に持つ。落下も墜落も無い。

物理っぽい要素は1つだけ入れてある。**機首を下げると速度が乗り、上げると削がれる**
（`diveAcceleration`）。これが無いと、どの姿勢でも同じ速度で進む「レール感」が出る。

**速度の下限は0より上**（既定18 m/s）。操作を止めても滑空し続けることが浮遊感の土台になる。

**飛行中も当たり判定を持つ**（K / 十字下で切り替え可）。当初はすり抜けにしていたが、
負荷を測るまでもなく**コライダーは9個・判定はカプセル1個ぶん**なので、外す理由が無かった。

ぶつかっても**止めない。** 接触した瞬間に速度へ0.6を掛けて掠める程度にする。急停止は
墜落と同じ体験になり、「落下でゲームオーバーにしない」方針（`CLAUDE.md` 不変条件3）と矛盾する。

高度の下限は**海面基準**（海面＋3m）。街の標高が場所によって17〜46mあるため、絶対値で
固定すると低い土地で弾かれる。海面の高さはシーン生成時に街の最下点から決めて渡している。

### 3.2 歩く（屋上・地面）

飛行中に**F / Xで着地**し、歩行中に**F / Xで飛び立つ**。真下へレイを飛ばして足場を探すので、
屋上でも地面でも降りられる。真下が海なら「足場がありません」と出て何も起きない。

都市側のMesh Colliderは試遊シーンの生成時に付ける（インポート時は付けない → `m0-plan.md` §3）。
**地域単位なら9個で済む。** 主要地物単位だと8千個を超えるので、その粒度で歩かせたくなったら
別の手が要る。**M0では粒度は描画負荷の話だったが、歩けるようにしたことで
粒度の選択がゲーム内容に影響するようになった。**

**地面にも屋上にも降りられる。** 地形にもコライダーが付く（2,500 x 2,045m・標高17〜46m）。
確認は`Tools > FeelFreeFlying > M1: 着地できる場所を調べる`で、街の何点かの真下に何があるかを
一覧で出せる。

| 値 | 既定 | 意味 |
|---|---|---|
| `walkSpeed` / `runSpeed` | 4.5 / 8.5 m/s | 歩き / 走り |
| `jumpSpeed` | 6.5 m/s | ジャンプの初速 |
| `gravity` | 22 m/s² | 歩行中のみ効く |
| `lookRate` | 130 度/秒 | 見回す速さ |
| `launchSpeed` / `launchPitch` | 16 m/s / 25度 | 飛び立つ時の初速と機首角 |
| `landingRayLength` | 400 m | この高さまでなら着地地点を探せる |

屋上から落ちても死なせない。高度の下限を割ったら自動的に飛行へ戻る。

### 3.1 調整値（`FlightController` / `FlightCamera`）

| 値 | 既定 | 意味 |
|---|---|---|
| `speedMin` / `speedMax` | **6 / 85 m/s** | 22〜306 km/h相当。**最初は18/110で「速すぎる」と判断された** |
| `speedStart` | **22 m/s** | 開始時（約79 km/h） |
| `throttleAcceleration` | 18 m/s² | スロットルへの追従 |
| `boostMultiplier` | 1.7 | ブースト時の倍率 |
| `invertPitch` | **true** | マウス上で機首上げ。Iキーで切り替え |
| `pitchRate` / `pitchLimit` | 55 度/秒 / 65度 | 機首の上下 |
| `rollRate` / `rollLimit` | 120 度/秒 / 70度 | 傾ける速さと限界 |
| `turnRate` | 60 度/秒 | バンクいっぱいで曲がる速さ |
| `autoLevelRate` | 25 度/秒 | 入力が無いとき水平に戻る速さ |

| `diveAcceleration` | 18 m/s² | 降下で乗る速度 |

| `rollInfluence`（カメラ） | 0.25 | ロールをカメラに反映する割合。1にすると酔う |
| `thirdPersonOffset`（カメラ） | (0, 0.5, -4.8) | **上げすぎるとマントを見下ろして身体が隠れる** |
| `firstPersonOffset`（カメラ） | (0, 0.14, 0.62) | 目の位置。伸ばした腕が視界に入る位置に置く |
| `firstPersonRollInfluence` | 0.7 | 一人称は強めに拾う。抑えすぎると首だけ動かない人形になる |
| `firstPersonSmoothing` | 0.03 秒 | **小さくする。** 視点＝目なので遅れがそのまま酔いになる |
| `fieldOfViewMin` / `Max` | 62 / 82度 | 速度に応じて広がる |

**試遊で感じたことと、触る値の対応**（迷ったらここを見る）。

| 感じたこと | 触る値 |
|---|---|
| 曲がらない / 曲がりすぎる | `turnRate`、`rollLimit` |
| 反応が鈍い / 敏感すぎる | `rollRate`、`pitchRate`、`attitudeSmoothing` |
| 速さを感じない | `followSmoothing`を上げる、`fieldOfViewMax`を上げる、`speedPullBack`を上げる |
| 速すぎて街が見えない | `speedMax`を下げる、`speedStart`を下げる |
| ふわふわしすぎ / 重い | `attitudeSmoothing`、`autoLevelRate` |
| 酔う | `rollInfluence`を下げる、`fieldOfViewMax`を下げる |
| 勝手に水平に戻って気持ち悪い | `autoLevelRate`を0にする |

### 判断（2026-08-09）: **続行**

`requirements.md` §8の「飛んで気持ちいいか。駄目なら中止」に対して、**続行**。
3つの問いのうち「街を見に行きたくなるか」と「プレイ感」に肯定の回答が出た。

確定した操作方式（§11の未決事項「飛行の操作方式」に対する答え）:

- **入力**: 傾けて曲がるバンク旋回。ヨーの直接入力は持たない
- **速度域**: 22〜306 km/h（6〜85 m/s）。**下限を大きく下げたことが効いた**
- **上下**: 反転が既定（マウス上で機首上げ）。切り替え可
- **視点**: **一人称が既定**。自分の姿は一人称では消す
- **上昇下降**: 機首角で行い、降下で速度が乗る。高度の下限は海面基準

要件側に反映が要るもの:

- `requirements.md` §9「カメラは三人称を基本とする」→ **一人称が基本**に書き換える
- 着地して歩けることは要件に無い機能。**M1の範囲を超えるが、街の見え方が変わるので残す**

次に出た要望: **実際のテクスチャで見たい**（→ §6）。

## 6. 実際のテクスチャで見たい（2026-08-09の要望）

いま出ている建物は**LOD1＋SDKのフォールバックテクスチャ**で、実際の建物の外観ではない。
PLATEAUには**LOD2（実写由来のテクスチャ付き）**があり、新宿区のデータには含まれている
（M0で取得済み。`Data/Plateau/` に約2万件のjpgがある）。

**ただし、これは決めてある方針2つと正面からぶつかる。**

1. **`CLAUDE.md` 不変条件6 / `requirements.md` §5「写実を目指さない」**
   データの粗さ（LOD1・テクスチャ無し）を前提に、様式化した見た目で設計すると決めてある。
   実写テクスチャを入れると、この前提そのものが変わる。
2. **`CLAUDE.md` 不変条件4 / `requirements.md` §4.2「実在建築物の名称・ロゴ・看板を出さない」**
   **LOD2のテクスチャは実際の建物を撮影したもので、看板・ロゴ・店名が写り込む。**
   形状は出してよいが名前は出さない、という線引きを、テクスチャは自動的に踏み越える。
   これは見た目の好みではなく権利の話（→ `~/AIFiles/docs/legal-review.md`）。

**方針を変えるかどうかはM1の判断とは別に決める。** まず実際に入れて、
「どう見えるか」「どれだけ重くなるか」「どれだけ容量が増えるか」を数字と絵で出す。
それを見てから、§5と§4.2を書き換えるか、様式化に戻すかを選ぶ。

### 6.1 実測（2026-08-09）

同じ範囲（新宿駅周辺2km四方・地域単位）を、LOD1テクスチャ無しと LOD2テクスチャ有りで比較した。
インポートはスクリプトの引数で切り替えられる。

```
-executeMethod FeelFreeFlying.EditorTools.M0CityImport.ImportFromCommandLine `
  -ffimport-granularity area -ffimport-lod 2 -ffimport-texture on
```

| | LOD1・テクスチャ無し | **LOD2・実写テクスチャ** |
|---|---|---|
| 描画対象 | 9 | 5 |
| 三角形 | 613,607 | **1,025,422** |
| マテリアル | 2 | 56 |
| avg fps | 653.0 | **905.6** |
| 1% low | 522.0 | 456.4 |
| min | 459.5 | 334.3 |
| 60fps以上 | 100.0% | **100.0%** |
| **ビルド後サイズ** | 542.6 MB | **1,748.9 MB** |
| インポート所要時間 | 約3分 | 約3分半 |

**速くなった。** 三角形が1.7倍でも平均fpsは上がっている。LOD1側が使っている
SDKのフォールバックマテリアル（三面投影のShader Graph）がピクセル単位で高価なのに対し、
LOD2は素直なテクスチャ付きLitで済むため。**「テクスチャを足すと重い」は成り立たなかった。**

**問題は容量。** 1地区で**+1.2GB**（542.6MB → 1,748.9MB）。M0で「10地区で1〜1.5GB規模」と
見積もったが、LOD2にすると同じ10地区で**12GB超**になる。同梱都市数の話が根本から変わる。

**そして看板が写る。** 屋上からの絵に、実在の店名・企業名・建物名がはっきり読める形で入っている。
`requirements.md` §4.2（実在建築物の名称・ロゴ・看板を出さない）は、この状態を許さない。
これは好みではなく権利の問題なので、**「見た目が良いから採用」では決められない。**

### 6.2 決定（2026-08-09）: **LOD2の形状を使い、実写テクスチャは使わない**

看板の問題（§4.2）と容量の問題を同時に解き、見た目の向上ぶんは受け取れるため。
**見た目が良くなった主因は窓や外壁の凹凸などの形状であって、写真ではない。**

| | LOD1（従来） | **LOD2・テクスチャ無し（採用）** | LOD2・実写テクスチャ |
|---|---|---|---|
| 三角形 | 613,607 | **1,025,422** | 1,025,422 |
| avg fps | 653.0 | 486.4 | 905.6 |
| 1% low | 522.0 | 264.4 | 456.4 |
| 60fps以上 | 100.0% | **100.0%** | 100.0% |
| ビルド後サイズ | 542.6 MB | **596.8 MB** | 1,748.9 MB |
| 実在の看板 | 出ない | **出ない** | **出る** |

容量増は**+54MB**で収まった（実写テクスチャなら+1.2GB）。

**fpsは下がった**（653 → 486）。三角形が1.7倍になったからではなく、SDKのフォールバック
マテリアル（三面投影のShader Graph）がピクセル単位で高価で、それが増えた面に掛かるため。
実写テクスチャ版が906fpsと最も速いことがその裏付けになっている。
**M5で自前のマテリアルに差し替えれば戻る見込み**——合格ラインの60fpsには8倍の余裕があるので、
M1の時点で手を入れる必要はない。

要件への反映（済）:

- `requirements.md` §5 — 「LOD1・テクスチャ無し前提」→「**LOD2の形状 + 自前のテクスチャ**」
- `requirements.md` §9 — 「三人称を基本」→「**一人称を基本**」
- `requirements.md` §11 — 出荷先・レンダーパイプライン・操作方式を確定済みに更新

M2へ持ち越す:

- **建物マテリアルの様式**（LOD2の形状に何を貼るか）。いまはSDKのフォールバックのまま
- インポートの既定値をLOD2に変更済み（`M0CityImport`）。**M0の計測値はLOD1時点のもの**なので、
  比較する時は条件を確認する

### 6.3 ランドマークだけ実写テクスチャにする（2026-08-09 実験）

「いくつかランドマークになる建物だけ実写テクスチャを入れられないか」を実際に作って測った。
**できる。** 手順は `M1LandmarkTextures`（`Tools > FeelFreeFlying > M1: ランドマークだけ実写テクスチャにする`）。

**どれをランドマークにするかは手で選ばない**（`CLAUDE.md` 不変条件7）。高さで上位N棟を採る。
手で選ぶと都市を追加するたびに人が選び直すことになり、パイプラインが止まる。
新宿の上位15棟は261m〜約150mで、都庁・コクーンタワー級が自動的に入る。

| | LOD2・全部様式化 | **LOD2・上位15棟だけ実写** | LOD2・全部実写 |
|---|---|---|---|
| 描画対象 | 5（地域単位） | 4,053（建物単位） | 5（地域単位） |
| avg fps | 486.4 | 442.9 | 905.6 |
| 1% low | 264.4 | 243.1 | 456.4 |
| min | 232.1 | 136.9 | 334.3 |
| 60fps以上 | 100.0% | **100.0%** | 100.0% |
| ビルド後サイズ | 596.8 MB | **776.2 MB** | 1,748.9 MB |

**代償は3つ。**

1. **建物単位（主要地物単位）に切り替えが要る。** 地域単位はメッシュが結合済みで、
   建物ごとにマテリアルを分けられない。描画対象が5個から4,053個になり、
   歩行用のMesh Colliderも4,053個になる（読み込みが重くなる）
2. **+179MB**（15棟ぶん）。アトラス解像度を4096pxのままにすると**+451MB**だった。
   **2048pxに下げて半分以下に落ちた**（`-ffimport-texres`で指定）。
   PLATEAUのテクスチャはアセットではなく**シーンに埋め込まれる**ため圧縮設定が効かず、
   解像度がそのまま容量になる
3. **看板の写り込みは建物ごとに確認が要る。** §4.2が禁じているのは名称・ロゴ・看板であって
   写真そのものではない。コクーンタワーや都庁のように外壁に店名が出ない建物は方針内だが、
   ALTAのように看板が主役の建物は外す必要がある。**高さ順で自動選出する以上、
   選ばれた建物を人が1度は見る工程が要る**（都市追加のたびに発生する）

**未解決: LOD2は全建物を持っていない。** LOD1にあってLOD2に無い建物が **625棟** あった
（`M1LodCoverageCheck`で確認）。LOD2だけを指定して取り込むと、それらは**黙って消える**。
M2のパイプラインでは「LOD2があればLOD2、無ければLOD1」で埋める処理が要る。
